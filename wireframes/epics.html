Notes

  1. New epic opens the existing new-task dialog with "Epic" already ticked. Its "first tasks" still turn into real tasks.
  2. Status filters are worked out from the epic's tasks, not stored. "Needs attention" overlaps the other filters, so its count is not added to them.
  3. Groups go from most to least urgent. An epic needs attention when any of its tasks is blocked or flagged for review, or when the epic or a task is overdue. Inside each group, the longest-stuck or soonest-due comes first.
  4. Why it's stuck is spelled out as counts. Each chip opens screen C filtered to just those tasks.
  5. The progress bar has one segment per workflow column, so you can see whether work is piling up in review or in QA, not just a percentage.
  6. Done epics are folded away so they don't push out live ones.
  7. The "No epic" row makes loose work visible. It links to the Board tab filtered to tasks without an epic.
Open: should epic status be worked out as shown (Not started = every task in To do; Done = every task in Done), or should you set it by hand? Worked out by default; the epic's stored column is then ignored.

Notes
